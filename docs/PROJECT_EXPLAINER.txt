1. Executive Summary

This repository delivers a comprehensive, thesis‑ready framework for training, conditioning, and systematically evaluating diffusion models that synthesise realistic financial return sequences for risk management and research. It brings together three variants: an unconditional (zero‑conditioned) baseline, a transparent explicitly conditioned model (market regime + target volatility), and a news‑aware LLM‑conditioned model that uses sentence‑embedding signals derived from daily news. The framework includes a complete experimental pipeline featuring pre-COVID training (2010-2019), out-of-sample stress testing (Experiment A), controllability assessment (Experiment B), and professional report generation. Collectively, these models and experiments aim to generate synthetic returns that are distributionally faithful, controllable, and rigorously validated for stress testing and risk assessment.

Why this matters: risk teams and researchers need realistic, controllable synthetic data to test portfolio behaviour under varying market regimes and news conditions. Standard historical bootstrapping is constrained by a single realised path. Classical models (e.g., GARCH) capture volatility clustering but struggle with broader controllability and multi‑factor conditions. Generative diffusion models can replicate stylised facts, target volatility or regimes, and respond—at least partially—to semantic signals (news). That translates into safer, faster experimentation; more robust back‑tests; and auditable, reproducible evidence.

The repository prioritises reproducibility (global seeding; deterministic CUDA flags; shared preprocessing); comparability (shared hyper‑parameters and CLI interfaces across models); systematic validation (hygiene checks, checkpoint verification, audit trails); and completeness (thesis‑grade figures, LaTeX tables, professional PDF reports, and consolidated metrics). You can: train all models with one command; run systematic experiments with standardized protocols; evaluate them side‑by‑side with unified scripts; and export publication‑ready outputs. The evaluation suite spans distributional fidelity (e.g., KS, simple MMD proxy, Wasserstein where available), risk back‑testing (VaR/ES, Kupiec coverage, a simple Christoffersen‑style independence ratio), controllability (target vs realised volatility, reliability curves), stylised facts (tails, ACF/PACF), systematic stress testing across multiple crisis periods, and comprehensive out-of-sample validation.

Where uncertainty remains, the repository is explicit: certain metrics (e.g., Diebold–Mariano tests, bootstrap confidence intervals) are referenced conceptually for completeness but are not fully implemented in code. Where this happens, we mark it clearly and offer suggested extensions. The end result is a practical, extensible foundation for thesis work and real‑world risk analysis that blends clarity, rigour, and accessibility.

4. Data and Preprocessing

4.1 Inputs
- S&P 500 daily close prices loaded from CSV.
- Log‑returns computed as r_t = log(Close_t / Close_{t-1}) and missing values dropped.

4.2 Sequence generation
- Create overlapping fixed‑length sequences X ∈ R^{N×1×T} via sliding windows (default T=60 days).
- Channel dimension (1) retained for 1D convolutional denoisers.

4.3 Conditioning features
- Explicit model: 4‑way market regime one‑hot [Up‑Low, Up‑High, Down‑Low, Down‑High] + target volatility σ*.
  • Trend from cumulative return sign over the window.
  • Volatility from mean of rolling standard deviations over the last vol_window values within the window, z‑scored using training split statistics.
- LLM model: daily news → sentence embeddings (all‑MiniLM‑L6‑v2) → per‑window mean → PCA to target dimension (default 64) → L2 normalisation.
  • Strict temporal alignment: forward‑fill only across trading days to avoid look‑ahead.
  • Embeddings cached under cache/news_embeddings/.

4.4 Splits and leakage controls
- Time‑based splits (typical default: 60% train, 20% validation, 20% test).
- No look‑ahead; each split uses conditioning derived only from its own period.

4.5 Assumptions and caveats
- Data file naming and columns: assumes a Close column; adjust loaders if you use different schemas.
- News: repository simulates finance‑like news if no API is connected; real news APIs would require API keys and rate‑limit handling.


5. Models and Conditioning

5.1 Diffusion backbone
- Denoiser: 1D dilated convolutional residual network with GroupNorm and SiLU activations.
- Time embedding: sinusoidal features + MLP.
- Diffusion schedule: cosine betas by default; DDPM/DDIM sampling supported; sample_steps configurable (e.g., 50).

5.2 Conditioning mechanisms
- FiLM (Feature‑wise Linear Modulation): scaling/shifting hidden features with conditioning vectors.
- Classifier‑Free Guidance (CFG): conditioning dropout during training (cfg_p) and guidance scale at sampling (cfg_scale).

5.3 Model variants
- Zero‑conditioned: same architecture, conditioning zeroed; unconditional baseline.
- Explicitly conditioned: regime one‑hot + σ*; transparent controllability (target vs realised volatility, regime probes).
- LLM‑conditioned: news‑derived embeddings; includes an auxiliary linear probe for volatility/trend interpretability.

5.4 Checkpoints and artefacts
- Each run: results/<model>/<run_id>/checkpoints/{best_model.pth, final_model.pth}; training_history.(csv|json); metadata.json; figures/; tables/; README_RUN.md.


6. Evaluation and Metrics

6.1 Distributional fidelity
- Kolmogorov–Smirnov (KS) test (two‑sample, real vs synthetic).
- Wasserstein distance (when available) as a distributional distance.
- MMD (Maximum Mean Discrepancy) proxy based on first two moments (simple, fast).
- Hill tail index approximation (upper‑tail heavy‑tailedness proxy).

6.2 Stylised facts
- Histograms with Gaussian overlays; ECDF; Q–Q plots for tails.
- ACF/PACF for returns and squared returns; volatility clustering indicators.

6.3 Risk metrics and back‑tests
- VaR/ES curves across confidence levels; exceedance timelines.
- Kupiec (unconditional coverage) back‑test; simple Christoffersen‑style independence ratio.
- Portfolio case study (COVID‑2020) with log‑return compounding and risk summaries.

6.4 Controllability
- Target vs realised σ* (scatter, reliability curves, residuals); regime confusion proxies.
- LLM‑specific: sentiment buckets/ablation proxies; controllability probe metrics (MAE, R²) for volatility/trend.

6.5 Statistical significance
- Pairwise KS comparisons across models.
- Assumption: Diebold–Mariano (DM) tests and bootstrap confidence intervals (CIs) are not currently implemented in code; add via statsmodels/scipy or bespoke routines if required for your thesis. Where referenced in summaries, treat as a roadmap item rather than an implemented feature.

9. Interpretation Guide

9.1 Non‑technical reading of outputs
- If KS is low and p‑value is not tiny, the synthetic returns resemble real returns.
- If VaR/ES curves behave sensibly and exceedance timelines do not show chronic under‑ or over‑coverage, the model’s tail risk is reasonably calibrated.
- If the explicit model’s realised volatility tracks target σ* (points close to the y=x line; reliability curve near identity), controllability is good.
- For the LLM model, large differences between sentiment buckets or ablations indicate sensitivity to conditioning; MAE/R² quantify how well the news proxy predicts volatility.

9.2 Technical notes
- KS and Wasserstein compare one‑dimensional return distributions aggregated across samples.
- The MMD proxy uses moment differences (simple, fast). For kernel MMD, extend utils/stats.py.
- Hill index is a rough tail‑heaviness indicator; interpret comparatively (between models), not absolutely.
- Kupiec assesses unconditional coverage at a given VaR level; independence ratios approximate Christoffersen’s test.
- Probe‑based controllability (LLM): predictions are in the scaled space; use the fitted scaler to interpret magnitude.


10. Troubleshooting and FAQ

Q: “FileNotFoundError: sp500_data.csv not found.”
A: Place a CSV at data/sp500_data.csv (with Close column) or set SP500_DATA_PATH. See Section 2.3.

Q: “No checkpoints found.”
A: Train first via python src/train_all.py. Evaluators auto‑discover results/<model>/latest/checkpoints/best_model.pth.

Q: “CUDA errors or out‑of‑memory.”
A: Fall back to CPU (--device cpu), reduce --batch-size, or enable --amp. Ensure CUDA versions match PyTorch.

Q: “Sentence‑transformers import fails.”
A: pip install -r requirements_llm_refactored.txt. The LLM model requires sentence‑transformers.

Q: “Plots fail on headless servers.”
A: Matplotlib Agg backend is enforced in scripts; ensure display is not required.

Q: “Results differ between runs.”
A: Use fixed seeds; avoid non‑deterministic flags (AMP/compile/DDP) if strict reproducibility is required.


11. Reproducibility and Compute Notes

- Determinism: global numpy/torch seeding; CUDA deterministic flags; benchmark disabled when determinism is prioritised.
- Shared preprocessing: identical returns, sequence slicing, and splits across models for fair comparisons.
- Checkpoint resume: training resumes automatically if a checkpoint exists (explicit/zero models in training pipeline).
- Performance vs determinism: enabling --amp/--compile or DDP can reduce strict determinism; document settings in metadata.json.
- Hardware: CPU‑only runs are supported; GPU accelerates training and evaluation markedly.


12. Security/Compliance and Data Usage

- Data: daily S&P 500 prices; no personal data processed. Ensure you have rights to the price data source you use.
- News embeddings: by default, the repository simulates finance‑like news; if integrating a real news API (e.g., NewsAPI), store API keys securely (environment variables, not in code), respect terms of service, and avoid logging raw articles.
- Generated data: synthetic returns are for research/testing; do not rely on them as trading signals without further validation.


13. Glossary

- VaR (Value at Risk): a quantile of losses over a horizon at a stated confidence level.
- ES (Expected Shortfall): mean loss conditional on exceeding the VaR threshold at the same level.
- KS test: non‑parametric test comparing two empirical distributions.
- Wasserstein distance: earth‑mover’s distance between distributions.
- MMD: discrepancy between distributions via kernel mean embeddings; here a simple moment‑based proxy is used.
- Hill tail index: estimator of tail heaviness for heavy‑tailed distributions.
- Kupiec test: back‑test of unconditional VaR coverage.
- Christoffersen test (independence): assesses clustering of VaR violations (here approximated via an independence ratio).
- DM test (Diebold–Mariano): statistical test for predictive accuracy differences; not implemented in code at time of writing (see Section 6.5).
- Bootstrap CI: resampling‑based confidence intervals; not implemented in code at time of writing.
- CFG (Classifier‑Free Guidance): sampling trick that blends conditional and unconditional predictions to amplify conditioning.
- FiLM: conditioning layer applying feature‑wise scale and shift to hidden activations.
